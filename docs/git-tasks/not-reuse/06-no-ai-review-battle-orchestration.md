# D6：不复用大型云端 AI 审查战斗编排

## 决策

不迁移 Grain 多模型互评、自动再跑、评审对战、长时间 review matrix 的 workflow 编排。

## 目的

让 DeepAuto 优先建立确定性验证和针对控制面边界的审查，而不是扩大不可预测的模型编排。

## 价值与意义

- 避免在 PR 流量、模型质量基线和结果消费协议尚未成熟时引入高成本系统。
- 让失败可定位：先分清是 lint、类型、测试、授权还是业务逻辑失败。
- 防止 AI review 被误当成可以替代测试、人工责任或分支保护的机制。

## 前置条件

无直接实施前置条件；只有当确定性 CI 稳定、人工 review 反馈数据充足且审查质量可量化时，才能重新评估。

## 执行与约束方案

1. 当前只使用本地 `code-reviewer` 与 `execution-safety-reviewer` 提供建议。
2. 任何云端审查试验必须只读、不能自动批准、不能自动合并、不能自动修改代码。
3. 试验前先定义基准样本、误报/漏报指标、预算上限和停用条件。

## 验收策略

- CI required checks 始终只依赖确定性验证和明确人工规则。
- 审查建议不会绕过 GitHub 分支保护或改变控制面状态。

## 人工决策

何时值得做只读试验；应基于实际 PR 规模、缺陷数据和预算，而不是因为 Grain 已经有该能力。
