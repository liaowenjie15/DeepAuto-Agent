# D4：禁止 Agent 直写默认分支、自动合并或自动部署

## 决策

DeepAuto Agent 只允许在受控任务分支创建提交和 Pull Request；禁止自动写入默认分支、自动合并 PR、自动生产部署或修改仓库设置。

## 目的

确保多用户平台不会因 Agent、错误授权或执行器故障扩大代码和生产环境影响范围。

## 价值与意义

- 人类保留合并与发布的最终责任。
- CI、安全审查和业务验收有明确插入点。
- 失败的 Agent 不会把不可逆修改直接带入默认分支。

## 前置条件

- GitHub App 与 Runner 令牌权限可限制为任务分支和 PR 所需范围。
- 控制面能记录 PR URL、head SHA、验证结果和人工审批状态。

## 执行与约束方案

1. Dispatcher 的写入策略默认是 `branch-and-pr`；不提供默认分支写入选项。
2. workflow 和代理 token 不授予管理仓库、绕过分支保护或部署生产的能力。
3. 用户提出自动合并/部署时，创建独立人工审批流程，而不是给通用 Agent 加例外。

## 验收策略

- Agent 尝试 push 默认分支、调用 merge API 或触发生产部署均被策略/权限拒绝。
- 正常代码任务仍可创建分支、提交、PR 和回传验证结果。

## 人工决策

未来若存在受控自动合并需求，必须单独立项并定义仓库、风险等级、审批人和回滚方案。
