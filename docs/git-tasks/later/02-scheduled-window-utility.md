# C2：定时巡检时间窗工具

## 目的

当 DeepAuto 出现工作日/自然日聚合报告时，提供可测试的时间窗计算，防止 cron 启动延迟导致漏查或重复统计。

## 价值与意义

- 将“本轮应检查哪段时间”变成确定函数，而不是散落在 shell 和自然语言中。
- 统一北京时区、工作日、节假日和补跑的口径。
- 让迟到触发、手动补跑和失败恢复仍能产出连续数据。

## 触发条件与前置条件

- 有明确的定时报告或巡检需求，并定义了数据源与负责人。
- 产品已决定按北京时间还是用户时区归档。
- 能取得可靠的节假日/调休来源；不能依赖硬编码年份表长期运行。

## 实现方案

1. 将 cron、触发时刻、时区、lookback 规则和补跑锚点放入独立纯函数模块。
2. 对工作日、自然日、首次运行、延迟触发、补跑和跨月写测试。
3. 工作流把计算出的 ISO 起止时间传给服务端查询，而非自行解析日期。
4. 数据报告记录实际窗口，便于事后审计。

## 验收策略

- 同一 cron 在准时、延迟和手动补跑下得到符合设计的连续窗口。
- 夏令时无关的北京时间逻辑有固定测试。
- 无法获取日历数据时显式降级或停止，不能默默按错误日期运行。

## 人工决策

- 是否需要中国法定工作日和调休支持；若没有面向中国团队的报告，此能力不值得引入。
- 补跑时是补齐缺口还是重新覆盖历史结果。

## 当前不做原因

DeepAuto 目前没有生产巡检或日报数据域，先建立这套工具会制造没有消费者的抽象。
