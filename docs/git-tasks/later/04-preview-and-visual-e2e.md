# C4：Preview 与视觉 E2E

## 目的

在 DeepAuto 拥有稳定 Web UI、Preview 环境和关键用户流程后，用真实浏览器验证任务创建、执行状态、取消和结果查看。

## 价值与意义

- 补足单元/集成测试无法覆盖的认证、前后端协议、部署配置和真实浏览器交互。
- 对 Agent 修改用户界面时提供可观察的验收证据。
- 避免仅凭截图或静态代码判断关键流程可用。

## 触发条件与前置条件

- 已有稳定、隔离、可自动清理的 Preview 环境和测试身份。
- 关键 E2E 断言不依赖真实用户数据、生产凭据或不可控第三方副作用。
- 有可靠的部署完成信号与失败截图/trace 存储策略。

## 实现方案

1. 先定义不超过 3 条关键流程：登录、创建受控任务、查看/取消执行。
2. Preview 只使用隔离数据库、测试 OAuth/飞书身份与受限工具能力。
3. 使用浏览器自动化生成 trace、截图和结构化断言；失败结果回写 PR 但不自动修改代码。
4. fork PR 默认走无密钥路径或直接跳过，不执行不可信 head 与受保护凭据的组合。

## 验收策略

- 关键流程的成功、权限拒绝、取消和 callback 延迟均可在 Preview 重现。
- 测试失败能定位为部署不可达、认证失败、UI 断言失败或后端错误。
- Preview 销毁后测试账号和临时数据被清理。

## 人工决策

- Preview 的生命周期、成本上限和是否对外可访问。
- 视觉断言是像素级、组件级还是仅流程级；建议先流程级。

## 当前不做原因

DeepAuto 当前的主要风险是控制面正确性和执行安全，Preview 会过早引入部署、域名、身份和数据清理负担。
