# C3：凭据与连接器可用性探针

## 目的

在多连接器进入生产后，主动检查飞书、GitHub、数据库、MCP 和外部服务的认证、scope 与基础连通性。

## 价值与意义

- 把“用户执行时才发现 token 过期或 scope 缺失”前移为平台可见故障。
- 可区分凭据问题、服务端故障、网络问题和策略拒绝，缩短排障路径。
- 为连接器健康状态和能力可用性提供基础数据。

## 触发条件与前置条件

- 至少两个以上外部连接器被真实用户使用，且凭据类型、轮换策略和 owner 已明确。
- 探针有最小权限的只读测试端点，绝不通过实际写操作验证连接。
- 有安全日志、告警收件人和凭据轮换流程。

## 实现方案

1. 每个连接器定义不可变的 probe contract：最小 scope、只读调用、超时、成功判据和错误映射。
2. 由受限服务端或专用健康 job 执行；不要让通用 Agent 自由探索凭据。
3. 输出仅保留状态、错误类型和关联凭据 ID，不记录 token、响应正文或用户资源内容。
4. 探针失败生成可操作告警：连接器、scope、过期/撤销/网络类别、责任人和下一步。

## 验收策略

- 模拟过期 token、缺少 scope、网络超时和上游 5xx，分类正确且不泄露凭据。
- 探针不会创建飞书文档、GitHub Issue、数据库行或外部任务。
- 禁用一个连接器后，Dispatcher 不会继续向用户宣称该能力可用。

## 人工决策

- 凭据健康状态是否对终端用户可见，以及可见粒度。
- 哪些连接器允许平台级 probe，哪些只能在用户实际授权上下文中按需验证。

## 当前不做原因

首期更需要保证连接器调用失败能正确返回；没有足够连接器与用户量时，主动探针的复杂度高于收益。
