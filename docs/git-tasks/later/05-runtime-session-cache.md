# C5：运行时会话缓存与续跑

## 目的

当同一会话中的长任务频繁续问时，在安全前提下复用 CLI runtime 上下文，降低冷启动与重复理解代码库的成本。

## 价值与意义

- 提升用户连续迭代代码任务的响应速度与上下文一致性。
- 减少重复读取仓库、重复安装依赖和重复解释任务的成本。
- 为故障恢复提供比“完全从零开始”更好的体验。

## 触发条件与前置条件

- 已证明冷启动成为真实的用户体验或成本瓶颈。
- conversation、调用者、workspace、仓库、分支和权限快照均有强绑定。
- 已完成取消、超时、缓存清理、敏感信息隔离和 Runner 被回收时的降级策略。

## 实现方案

1. 控制面计算稳定 session key，不允许 CLI/runtime 自己按自由文本命名会话。
2. 缓存仅保存可安全复用的运行时状态；凭据始终按每个 Attempt 重新领取。
3. 恢复前校验调用者、工作区、仓库、分支、权限范围和策略版本一致。
4. 缓存命中失败时必须安全回落到新会话，并保留诊断信息。

## 验收策略

- 同一合格 conversation 可恢复；跨用户、跨工作区、权限收缩或仓库变化时被拒绝。
- 取消后缓存不含继续执行的后台进程、token 或未提交的未知状态。
- 缓存被删除、Runner 重建或版本升级后，任务能以新会话继续而不损坏状态机。

## 人工决策

- 最大缓存时长、存储位置、成本预算和是否允许跨设备续跑。
- 是否允许带有未提交修改的会话恢复；安全默认是不允许，除非工作区快照可验证。

## 当前不做原因

会话缓存会把身份、工作区和状态污染问题放大；必须晚于授权、审计、取消和执行隔离完成。
